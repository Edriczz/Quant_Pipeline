# Workflow Index — ASML OU Mean-Reversion Pipeline

**Start here. Read this file first, every session, before opening any
phase file.**

This build is split into three ordered documents. Work through them
**in this exact order**, and within each document, **in the order the
phases are listed**. Do not skip ahead. Do not start a phase until the
previous phase's validation gate has passed.

| Order | File | Covers | Depends on |
|---|---|---|---|
| 1 | `01_foundation.md` | Phases 0–4: scaffold, config, models, loader, stationarity, base estimator | `PROJECT_RULES.md` |
| 2 | `02_estimators.md` | Phases 5–7: OLS, Kalman, integration check | `01_foundation.md` complete |
| 3 | `03_app_and_ship.md` | Phases 8–10: interpretation, Streamlit, polish/deploy | `02_estimators.md` complete |

**Companion file:** `PROJECT_RULES.md` (repo root, or `docs/`) defines
*how* every component must be written (OOP structure, typing, testing
conventions). This index and the phase files define *what order* to
build and verify things in. Always follow both together.

## How to resume work mid-project

If you are picking this project back up (new session, new context
window), do the following before writing any code:

1. Open this index file.
2. Check the repo's actual state against the phase files in order —
   find the **first** phase whose Gate is not yet satisfied. That is
   your starting point, regardless of what phase you last remember
   working on.
3. Open only the phase document that contains that phase. You do not
   need the other two phase documents loaded to continue working
   correctly, as long as you trust the gates already passed.

## Global rule (applies across all three files)

Follow each phase in order. Do not start a phase until the previous
phase's validation gate passes. Each phase document ends with an
explicit pointer to the next document — follow it rather than assuming.
